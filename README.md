# messenger-bridge

Мост между мессенджерами: один канал назначается **главным** — в нём ты читаешь всё
и отвечаешь; остальные каналы присылают туда свои сообщения и получают ответы
и действия (реакция, прочтение, «печатает», правка, удаление).

Сейчас подключены два канала: **Telegram** (от имени твоего бота) и **MAX**
(от имени твоего аккаунта, через [`PyMax`](https://github.com/MaxApiTeam/PyMax) —
неофициальный внутренний API). Новый мессенджер добавляется одним адаптером.

```
MAX ─┐                                    ┌─ текст, фото, видео, файл, голосовое
     ├─→ главный канал (например Telegram) ─→ реакция, прочтение, «печатает»,
TG ──┘   подпись «MAX · Лера», ответ reply     правка, удаление → обратно в источник
         уходит в тот же чат того же канала
```

**Важно про MAX:** это не официальный Bot API. Использование внутреннего API нарушает
условия MAX, аккаунт могут ограничить. Не рассылай спам и массовые сообщения.
Официальный путь (`dev.max.ru`) не подходит: бот не может писать людям первым и не
является твоим аккаунтом.

## Установка

```bash
pip3 install -r requirements.txt
```

## Настройка

```bash
cd /mnt/projects_ssd/Projects/max-tg-bridge
cp .env.example .env
$EDITOR .env
```

- `TG_BOT_TOKEN` — токен бота от [@BotFather](https://t.me/BotFather).
- `MAX_PHONE` — номер аккаунта MAX в формате `+7...`.
- `OWNER_TG_ID` — твой Telegram id (если пусто — владельцем станет первый, кто напишет боту).
- `TG_API_BASE` — необязательно. Адрес Bot API, если бот ходит не на `api.telegram.org`,
  а на локальный сервер (`http://127.0.0.1:8081` — контейнер `telegram-bot-api --local`).
  Тогда TG-трафик тянет демон, самому боту VPN не нужен, а MAX может ходить напрямую.
- Любую настройку из `/settings` можно задать заранее: `BRIDGE_<КЛЮЧ>=1|0`, например
  `BRIDGE_GET_CHANNELS=1`, `BRIDGE_QUIET_HOURS=1`, `BRIDGE_LIMIT_TO_MAX=200`
  (полный список — в `.env.example`). Значение из `.env` действует, пока галочку
  не тронули руками в боте.

## Первый запуск

```bash
./run.sh
```

- MAX попросит SMS-код прямо в терминале (и 2FA-пароль, если он включён). Сессия
  сохранится в `data/max.db`, дальше код не нужен.
- В Telegram напиши боту `/start`.

## Команды в главном канале

Интерфейс один и тот же во всех каналах. Меню строит ядро: где канал умеет кнопки
(Telegram) — рисуются кнопки, где не умеет (MAX) — тот же список нумерацией, и номер
означает ровно то же действие, что нажатие кнопки. Текстом в любом канале работает форма
`/settings <номер> <значение>`.

| Команда | Что делает |
|---|---|
| `/chats` | чаты всех каналов: писать, история, игнорить |
| `/chats short` | компактный вид списка (только имена, кнопками) |
| `/chats long` | подробный вид: карточками с аватарками |
| `/chats readonly` | только те чаты, куда писать нельзя (каналы, «пишут лишь админы») |
| `/history` | история переписки: активный чат или чат из reply, по 8 на страницу |
| `/settings` | настройки: кнопками или нумерованным списком |
| `/settings 16 200` | поменять настройку по номеру (вкл/выкл, число, имя канала) |
| `/to max:367115027 текст` | написать в конкретный чат конкретного канала |
| `/to +79991234567 [текст]` | найти человека в MAX по номеру |
| `/stop` | сбросить активный чат |
| `/me` | какие каналы подключены и какой главный |

Контактом из Telegram тоже можно: перешли боту контакт — он найдёт номер в MAX и
сделает этот чат активным.

## Как ходят сообщения

- Сообщение из любого канала-источника приходит в главный с подписью `MAX · Лера`.
- **Ответ (reply) на такое сообщение** уходит обратно в тот же чат того же мессенджера,
  даже если активный чат выбран другой. Без reply — в активный чат.
- Правки и удаления приходят ответом на исходное: `[Изменено] новый текст` и `[Удалено]`.
  Само исходное сообщение не редактируется.
- Статусы прочтения: `MAX · Лера` + `[Прочитано]` — на одно прочитанное сообщение reply'ом,
  на пачку — отдельным сообщением. Когда собеседник пишет текст, этот статус подменяется текстом.
- Реакция в источнике: **ставится реакция на то же сообщение в главном** (если Telegram знает
  такой emoji) и приходит уведомление `[Реакция] 👍×2`.
- «Печатает…» показывается в главном. В MAX отправить «печатает» нельзя — PyMax 2.5.0
  не умеет опкод `MSG_TYPING`, поэтому в эту сторону действие пропускается.
- Игнорируемые чаты не пересылаются, но **пишутся в историю** — их видно в `/history`:
  записи идут сверху вниз от свежих к старым, по одной в строке, с подписью автора
  (`Я: текст`, `Лера: текст`), устаревшие версии помечены `[Удалено]`.

## Настройки (`/settings`)

Страницы листаются кнопками ◀ ▶:

1. **Главный канал** — куда сходятся сообщения (✓ текущий): нажатие открывает меню
   с кнопками каналов, `max_inbox` — в какой чат MAX падают чужие сообщения
   (0 = «Избранное»);
2. **От кого получать** — каналы, служебные аккаунты («Безопасность», «Коды подтверждения»),
   чаты «Групповой звонок», Избранное;
3. **Уведомления** — статусы прочтения, правки, удаления, реакции, «печатает…»;
4. **Прочее** — пересылка голосовых и кружков, вид списка чатов (`long` — карточками
   с аватарками, `short` — списком имён), автоотметка прочитанным, тихие часы;
5. **Числа и часы** — лимиты размеров файлов (в источник и из источника, МБ), часы тишины:
   нажатие спрашивает новое значение, его нужно написать сообщением (отмена — `/cancel`);
6. **Списки** — игнорируемые чаты с кнопками «вернуть».

Что уже учтено в списках: список сортируется по каналу, а внутри канала — по свежести
последнего контакта (сообщение, звонок, реакция), свежие сверху и по одному чату в строке;
забаненные и удалённые аккаунты MAX (`account_status` не 0 или профиль не отдаётся)
не показываются; каналы MAX не пересылаются; служебные чаты («Безопасность»,
«Коды подтверждения») и старые «Групповые звонки» скрыты; чат `id 0` подписан «Избранное»;
чаты «только для чтения» помечены и попадают в `/chats readonly`; аватарки кэшируются
в Telegram по `file_id` и повторно не загружаются.

## Если главный канал — MAX

Переключается в `/settings` → «Главный канал» (или `BRIDGE_HUB_CHANNEL=max` в `.env`).

- Сообщения из источников падают в чат `max_inbox` (по умолчанию `0` — «Избранное»)
  с подписью `VK · Маша` и т.п.
- **Ответ (reply) в Избранном** уходит обратно в чат источника — маршрут берётся из
  ReplyLink. Без reply — в активный чат.
- Кнопок в MAX нет, поэтому меню приходит нумерованным списком — те же пункты, что
  в Telegram кнопками. Пишешь номер, и выполняется то же действие: выбрать чат,
  открыть историю, игнорить, переключить настройку, листать историю.
  Список чатов — `/chats`, история — `/history`, настройки — `/settings`
  (или сразу с номером и значением: `/settings 16 200`).
- Прочитал пересланное в Избранном — в источнике сообщение тоже отмечается прочитанным.
- «Печатает» в сторону MAX не отправляется: PyMax 2.5.0 не умеет опкод `MSG_TYPING`.
- Панель управления (кнопки, карточки чатов с аватарками) остаётся в Telegram —
  `bot.py` работает независимо от того, какой канал главный.

Смысл в MAX-как-главном появляется, когда есть источник, умеющий видеть чужие сообщения
(например, мост в VK/WhatsApp): тогда MAX — хаб, а Telegram — панель. Сам Telegram
источником быть не может: это бот, он видит только владельца.

## Файлы

```
main.py               — сборка: хранилище, настройки, каналы, ядро, запуск
bridge.py             — правила моста: маршруты «источник ↔ главный», история, уведомления
settings.py           — реестр настроек (умолчания, .env, sqlite) и их страницы
store.py              — sqlite: владелец, активный чат, маршруты, история, мьюты, настройки
channels/base.py      — интерфейс канала: Incoming, Change, Media, ChatRef + действия
channels/telegram.py  — Telegram-канал (aiogram): отправка и приём в нейтральном виде
channels/max.py       — MAX-канал (обёртка над max_side): события и действия
max_side.py           — низкий уровень MAX: логин, отправка, вложения, чаты
bot.py                — интерфейс главного канала в Telegram: команды, карточки, настройки
data/                 — сессия MAX (max.db), state.sqlite3, bridge.log
```

### Как добавить мессенджер

1. Написать адаптер в `channels/<имя>.py` с методами из `channels/base.py`:
   `start/stop`, `send_text`, `send_media`, `show_typing`, `react`, `mark_read`,
   `edit_text`, `delete`, `list_chats`, `chat_flags`; события отдавать через
   `Incoming` и `Change`.
2. Зарегистрировать его в `main.py` в словаре `channels`.
3. Ядро и интерфейс менять не нужно: он появится в `/chats`, в странице
   «Главный канал» и получит все действия автоматически.

## Автозапуск (systemd --user)

`~/.config/systemd/user/messenger-bridge.service`:

```ini
[Unit]
Description=Messenger bridge (hub + sources)
After=network-online.target

[Service]
WorkingDirectory=/mnt/projects_ssd/Projects/max-tg-bridge
ExecStart=/usr/bin/env python3 main.py
Restart=on-failure
RestartSec=10

[Install]
WantedBy=default.target
```

```bash
systemctl --user daemon-reload
systemctl --user enable --now messenger-bridge
```

При автозапуске сессия MAX должна быть уже создана первым интерактивным запуском.
